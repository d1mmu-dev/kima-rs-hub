# M5 Vibe Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed-in user opens "similar tracks" on a song and gets upstream's ranking (sound + feel + genre, at most 2 per album and 4 per artist); types "rainy evening jazz" and gets the nearest tracks; blends songs with alchemy; asks for a path between two songs; polls `GET /api/vibe/map` and receives every track's stable 3-D position and colour, plus mood shares for the collection page — all computed by Rust from the CLAP vectors M4 stores, with new tracks placed without moving old ones.

**Architecture:** A new pure crate `kima-vibe` (formula, exact math, UMAP layout, mood arithmetic, song path, zero-shot arithmetic; no sqlx/tokio/ort) is called by `kima-db::vibe` (migrations, one `ELIGIBLE` SQL fragment, state/feel/mood/map queries, ranking), `kima-ident` (two new library-wide coordinator phases `mood` and `similarity`, asset loading, single-flight map task) and `kima-api` (seven `/api/vibe/*` routes, progress/rerun wiring). Scoring stays in SQL (pgvector) exactly as upstream; the O(n²) neighbour sweep and layout run on a blocking thread pool.

**Tech Stack:** Rust 2024, axum 0.8, sqlx 0.8, tokio, Postgres 17 + pgvector 0.8 (`pgvector/pgvector:pg17`, 0.8.7 observed), `rayon` (new, `kima-vibe` only, behind the `parallel` feature), `serde_json`, `sha2`. No new native dependency.

## Global Constraints

- Everything in M0–M4's Global Constraints still holds: GPL-3.0-only, edition 2024, camelCase JSON with `{"error": "<message>"}`, UUIDv7 ids, **the database is never mocked**, no test reaches the network, commits authored `dimmu <3417783+d1mmu-dev@users.noreply.github.com>` with **no** `Co-Authored-By` or AI line (check `git config user.name/email` in every new worktree).
- **Before every commit:** `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings` (also `+stable` once per phase; CI runs latest stable), the touched crates' tests; after any `query!` change `cargo sqlx prepare --workspace -- --all-targets` **from the repo root** and commit `.sqlx/` in the same commit; after adding a migration, touch the file that holds `sqlx::migrate!` so the embedded set is rebuilt.
- **Tests that mutate a database** run only against a run-owned isolated Postgres on `127.0.0.1` (never the dev DB on 5456, never a reused volume); verify `current_database()` before seeding; bounded batches (< 300 s per package, ≤ 420 s total); a zero-exit with no test output is not evidence.
- **TDD:** each task's first step writes the failing tests it names and runs them red; only then implement. A weakened assertion is a review finding.
- **Model/asset rights:** no probe, head, model or reference-output bytes are copied into Git until the owner has answered Q3; `kima-vibe` tests use only the **synthetic** fixtures of Task 0. Real-asset tests are `#[ignore]`, read `KIMA_VIBE_ASSET_DIR`/`KIMA_CLAP_MODEL_DIR` and **panic** when unset.
- **Exactness:** formula constants, tie rules, error strings, limits and response keys are upstream's (spec §5-§8). A deliberate difference is a D-row in the same commit (D-181–D-195); never edit an applied migration.
- **One eligibility fragment:** every vibe query goes through `kima_db::vibe::ELIGIBLE` (spec §6.5). A source-grep test fails on a `track_embeddings` read in `kima-db/src/vibe/` that does not.
- **Lock order** (copy of upstream): `matching_state`/`mood_state` row first, then feel/score/map rows, then track rows; a re-run deletes the state row first.
- **No Next.js work.** Frontend pages are M10 (spec §13).

## Review Focus

1. **Eligibility and gating drift.** A vibe query that forgets the model gate reads vectors from the wrong checkpoint (spec §2.3); one that forgets `missing_since` offers deleted songs. The `ELIGIBLE` grep test and the "missing file disappears at once" and "other-model vector ignored" tests (Tasks 3, 6) are the guard.
2. **Rebuild races** (Tasks 5, 10, 12): a layout overtaken by a re-run must not store the old map; a build that waited behind a re-run writes nothing; no deadlock between a re-run that deletes vectors and a map write. These are upstream's four hard tests and need real concurrent transactions.
3. **Permanent-layout rule.** The first layout is permanent; nothing already placed may move on a later pass (Task 10 test "never moves a track that has a place").
4. **Exact arithmetic.** The ported `exact_math`, PRNG order and `optimize` loop are compared with frozen goldens; an "equivalent" refactor that reorders float operations is a finding (Tasks 1, 9).
5. **Scope fences.** No mixes, recipes, tags, stations (M5b); no UI; no public vibe feed in Phases A–D; MusiCNN/DSP absence handled only by the degradations in spec §8.1.
6. **Asset handling.** Fail closed on missing/mismatched hash, per-capability degradation, bytes verified are the bytes parsed (M4 pattern: open no-follow/non-blocking, bounded read, `fstat` regular file).
7. **Large-library behaviour.** No handler loads the whole library except map and the blocking passes; the map and the path service have size limits (Tasks 9, 13, 15).
