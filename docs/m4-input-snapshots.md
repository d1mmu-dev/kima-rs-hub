# M4 encoded input snapshots

The embedding stage decodes a private, unnamed per-attempt copy-on-write clone of the encoded input, never the live library file.

## Requirements and deployment (security change: read-write library)

* Linux with `openat2` (5.6+), `statx`, `O_TMPFILE`, `FICLONE`, and a reflink-capable filesystem (verified on local Btrfs; XFS reflink, etc. depend on kernel/filesystem/mount configuration and are not presumed; tmpfs rejects cloning).
* **One shared read-write mount** holds both the library and the private snapshot directory (owner decision). The earlier `ro` library mount no longer works for embeddings: a reflink needs a destination on the *same* mount, and a destination needs write access. Isolation is therefore provided by UID, permissions and ACLs of the snapshot directory, not by a read-only flag. The mount is read-write for the container; whether the server *account* can write elsewhere in the library is decided by filesystem permissions: it needs write only in the snapshot directory (the organizer's move/copy modes need more, as before).
* **Deployment (`docker-compose.yml`)**: `${MUSIC_DIR:-./music}:/music` (no `:ro`) and `KIMA_SNAPSHOT_DIR=/music/.kima-snapshots`. `docker/entrypoint.sh` runs as root before dropping to `kima` and does `install -d -m 0700 -o kima -g kima "$KIMA_SNAPSHOT_DIR"` (refusing a symlink; a failure is only logged, because the server then disables embeddings itself). The host directory therefore gains a `.kima-snapshots` directory owned by the container's `kima` UID; the host filesystem must support reflinks (Btrfs; XFS with `reflink=1`; not ext4/tmpfs/overlayfs).
* **The library scanner never indexes it**: `scan.rs` filters every dot-prefixed directory (`is_hidden` in `filter_entry`), and the watcher ignores hidden components too. The unnamed `O_TMPFILE` snapshots have no directory entry at all, so even a scanner that listed the directory would find nothing; confirmed by reading the code and by the test `snapshot_is_unnamed_private_and_leaves_no_entries` (the snapshot directory stays empty while a snapshot lives). If you choose a non-dot name, add it to the scanner ignore list.
* `KIMA_SNAPSHOT_DIR`: absolute path of the private directory, no `..`. It must exist, contain no symbolic link in its path, be owned by the server's effective UID and have no group/other mode bits (`0700`); otherwise opening fails closed. Mode bits and ownership are the only checks: POSIX ACLs, capabilities, LSM policy and other processes of the same UID or root are not examined and not isolated. Unset: **audio embedding is off**: no embedding work is claimed and the `clap_audio_embedding` capability is `unavailable` with the reason `KIMA_SNAPSHOT_DIR is not configured` (a warning is logged at startup). CLAP text embedding is independent and keeps working.
* **Fail-fast at startup**: when `KIMA_SNAPSHOT_DIR` is set, the server opens it, compares its mount ID with the library root's and probes reflink support in it (`check_snapshot_setup`; ext4, overlayfs and tmpfs fail here with a readable reason). Any failure (missing, not private, `..` in the directory or root, different mount, no reflink) is logged as an error; the server **still starts**, but *audio* embedding is blocked: no work is claimed and `clap_audio_embedding` is `unavailable` with that reason. This is separate from `DISABLE_CLAP` (which disables audio **and** text): CLAP text embedding and the operator switch are untouched, so the status never says `DISABLE_CLAP is active` for a snapshot problem.
* **Library root changed at runtime** (organizer switch, `LibraryRoot::set`): before each embedding batch the root is compared with the one last checked; a new root is checked against the snapshot directory's mount again (cached per root). If it is on another mount, audio embedding claims nothing, a warning is logged and the status shows the reason; switching back clears it. Per-attempt mount checks stay as the last line of defence.
* **Global failure stops audio until restart**: the first `SNAPSHOT_UNAVAILABLE` (snapshot directory, `O_TMPFILE`, reflink, `ENOSPC`, quota, procfs, ...) latches the first infrastructure reason in the process-shared embedding runtime. It stops the phase; unstarted claims are released to `pending`, while already-running failures close as `INCONCLUSIVE` with a 60 min delay, without consuming attempts. Later batches/cycles claim **nothing** while latched, even after permissions/space are repaired or the organizer root changes. `GET /api/enrichment/status` → `mlCapabilities.capabilities.clap_audio_embedding` reports `state: unavailable`, category `io`, the original reason and the repair-and-restart instruction. Independent CLAP text is untouched. **Recovery:** repair space/quota/permissions/mount/procfs, then restart; startup revalidates infrastructure and model bytes. There is no timer probe, per-file recovery probe, status-read side effect or live reload. The failed track retains its existing retry due time; restart does not reset per-track state. A root-check-only block (no attempt has failed) still clears on switching back to a valid root, as above.
* **Known limits / operator notes**
  * `SNAPSHOT_TOO_LARGE` and `SNAPSHOT_INVALID_PATH` are terminal per track; there is no repair path other than changing the file (shrinking it, or replacing a symlink component / bad name by a real one), or raising `KIMA_SNAPSHOT_MAX_BYTES` for `TOO_LARGE` and reopening the stage.
  * A library root that is itself a symlink (or has a symlink component) is refused: the root is pinned without following symlinks, so embedding is blocked (`check_snapshot_setup` fails). Point `MUSIC_PATH` at the real directory.
  * NFS with `root_squash`: the server must own the snapshot directory as its effective UID; a squashed root cannot create or own it, and O_TMPFILE/FICLONE support depends on the server (NFS 4.2 clone). If it fails, audio embedding is blocked with the error.
  * The snapshot directory `.kima-snapshots` is visible in the library on the host (owned by the container's `kima` UID). The scanner ignores it (dot directory); other tools that index the library folder may not.
  * Read-only library: not supported for embeddings (a reflink needs a writable destination on the same mount). Alternatives: disable embeddings (`DISABLE_CLAP=true`, or leave `KIMA_SNAPSHOT_DIR` unset to switch off audio only) or put the library on a separate read-write mount with reflink support that also holds the snapshot directory.
* `/proc` must be the genuine procfs of the process's own mount namespace. Reopening the `O_PATH` source and the snapshot (independent offsets per decode pass) goes through `/proc/self/fd/N`; a hostile or remounted `/proc` is outside the threat model. The library root and each input must be absolute/relative with no symlink components.

## Algorithm

1. The library root is opened once as an `O_PATH` directory descriptor (`openat2`, `RESOLVE_NO_SYMLINKS`); the snapshot directory is pinned the same way once per store. Pinning is by inode: renaming the root path afterwards does not redirect later steps.
2. The source is resolved by a **single** `openat2(root_fd, full_relative_path, O_PATH, RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_XDEV)`. No parent directory is opened separately, so there is no window in which a parent can be moved or replaced between steps. A parent moved outside the root, or replaced by a symlink, makes the call fail; a basename replaced after resolution does not matter, the already-resolved inode is used. Relative paths with `..`, `.`, empty or absolute components are rejected before any syscall.
3. `statx` on the open descriptor: must be a regular file (FIFOs, devices, directories refused), size at most the configured limit. Every `statx` use requires `stx_mask & mask == mask` for the fields it reads (type, size, inode; mount ID: the unique or the legacy one); an unreported field is an error, not a zero.
4. `statx(AT_EMPTY_PATH)` mount IDs of root, snapshot directory, source, reopened source and snapshot must be equal. `STATX_MNT_ID_UNIQUE` is preferred; the legacy `STATX_MNT_ID` is used only if the kernel does not report the unique one, and only IDs of the same kind are compared. Missing mount-ID data, differing values or mixed kinds are errors.
5. The source is reopened read-only (`O_NONBLOCK`) through `/proc/self/fd` and checked to be the same device/inode and regular.
6. `O_TMPFILE|O_RDWR|O_CLOEXEC`, mode 0600, relative to the private directory descriptor (not the source's directory), is cloned with `FICLONE`. `EAGAIN` is retried at most 3 more times (5 ms apart); every other error, including `EXDEV`/`EOPNOTSUPP`/`EINVAL`, fails. **There is no copying fallback.** The raw `openat2`, `statx`, `openat(O_TMPFILE)` and `ioctl(FICLONE)` calls are retried on `EINTR` (std's `open` for the `/proc/self/fd` reopen does so itself). The `FICLONE` request is passed as `FICLONE as _`, so it fits `libc::ioctl`'s `c_ulong` request on glibc (the Docker image) as well as the `c_int` one on musl.
7. After the clone the snapshot size is re-checked against the limit (a source that grew in between fails).

Every failure releases all descriptors and the concurrency slot. The concurrency slot is taken with a compare-and-swap loop (the counter never exceeds the limit) and is held by the snapshot **and by every file returned from `InputSnapshot::open()`** (`SnapshotFile`, an `Arc` to the slot): it is released only when the last descriptor onto the unnamed inode is dropped, even if the `InputSnapshot` itself is gone. `SnapshotFile` implements `Read`, `Seek` and symphonia's `MediaSource`. The unnamed inode disappears when its last descriptor closes, including on process exit; on cancellation a running blocking task keeps it until the task exits.

## Limits (configurable; defaults are this change's choice, not from the spec)

| Variable | Default | Meaning |
|---|---|---|
| `KIMA_SNAPSHOT_MAX_BYTES` | 2 GiB | largest input snapshotted; larger inputs fail the attempt |
| `KIMA_SNAPSHOT_MAX_CONCURRENT` | 2 | snapshots alive at once in the process; extra attempts fail with `SNAPSHOT_UNAVAILABLE` (they are retried later) |

The embedding worker semaphore (`EmbeddingConfig::workers`, currently 1 in the server) already bounds blocking attempts including cancelled ones; the snapshot limit is a second, independent bound. No decode-duration or disk-quota limit exists. A reflink shares blocks until either side is written, so concurrent writes to a source can consume space proportional to the changed data, and clone/metadata operations can fail for lack of space or quota. The size check uses the file's size and says nothing about decoded memory.

## Error reporting

`SnapshotStore::create` returns a `SnapshotError` with a `SnapshotClass`. Constant properties of the input file are terminal; unreadable files retry with a bounded budget; environmental failures never consume the per-track attempt budget and latch the audio infrastructure block until restart.

| Class | Detected as | Embedding stage records |
|---|---|---|
| `Missing` | `ENOENT` resolving the source beneath the root | `FILE_MISSING` (class `FILE_MISSING`, as before) |
| `TooLarge` | `FileTooLarge`: size over the limit, or growth during the clone | `PERMANENT` / code `SNAPSHOT_TOO_LARGE` |
| `NotRegular` | directory, FIFO, device | `PERMANENT` / code `SNAPSHOT_NOT_REGULAR` |
| `InvalidPath` | absolute/`..`/`.`/empty relative path, `ELOOP` (symlink), `ENOTDIR`, `ENAMETOOLONG` | `PERMANENT` / code `SNAPSHOT_INVALID_PATH` |
| `Unreadable` | `EACCES`/`EPERM` resolving or reopening the source, `EXDEV` (source or a parent on another mount, `RESOLVE_NO_XDEV`), source mount ID differing from the root's | class `INCONCLUSIVE` / code `SNAPSHOT_UNREADABLE`, attempt **counted**, retries on the normal schedule (1 min, 10 min, 1 h; terminal at the 4th failure, `RETRY_CAP`), then terminal; other files and the phase are unaffected |
| `Infrastructure` | everything else: `QuotaExceeded` (concurrency limit), `EAGAIN` after the retries, snapshot directory unset/missing/not private, relative or `..` root, mount-ID mismatch of root vs snapshot directory/snapshot or missing mount-ID data, `EXDEV` of the clone, no reflink (`EOPNOTSUPP`/`EINVAL`), `EROFS`, `ENOSPC`, reopen/procfs failures | `SNAPSHOT_UNAVAILABLE`, class `INCONCLUSIVE`, delayed retry, attempt not counted |

An unset or unopenable snapshot directory is always `Infrastructure` (never mistaken for a missing input file). A runtime infrastructure failure updates audio capability status as well as the active track report; permanent per-file and `Unreadable` failures do not change capability status. Decode failures after a snapshot is opened keep their normal classification; a failed reopen of an existing snapshot is `SNAPSHOT_UNAVAILABLE`. Redelivery limits are separate. Unlike the fingerprint stage, `Missing` is reported at once without the "file moved/back" re-check.

## What a snapshot does NOT prove

A per-file clone is not a transaction with an external writer: it cannot show that a multi-write update was complete when cloned, that the source is still current at publication, or detect every replacement. Database generation fencing is separate and not a substitute for a filesystem change detector. Other generic decoding APIs do not automatically acquire a snapshot.

## Not covered by automated tests

* Real bind mounts are covered by `tests/input_snapshot_mounts.rs`, which is `#[ignore]`d because it needs mount rights; run it with `unshare -Urm cargo test -p kima-ml --test input_snapshot_mounts -- --ignored` (works without root where unprivileged user namespaces are enabled). It checks `RESOLVE_NO_XDEV` (`EXDEV`, class `Unreadable`) on a mount inside the library and a mount-ID mismatch of a bind-mounted snapshot directory. Mount-ID mismatches of each individual comparison (root vs directory, source, reopened source, snapshot) are tested with injected IDs.
* Positive tests need a reflink filesystem and **fail with an explicit `NO REFLINK SUPPORT` message** otherwise; with `KIMA_TEST_ALLOW_NO_REFLINK=1` they print `SKIPPED: ...` to stderr and return instead. Their temporary directories live in the crate directory (inside the checkout, Btrfs on the dev box) or, when set, under the absolute `KIMA_TEST_REFLINK_DIR`; hosted CI sets it to a loop-mounted XFS (`reflink=1`) because the runner's ext4 has no reflink.
* Filesystems other than Btrfs and tmpfs (e.g. overlayfs, NFS); XFS only through the hosted CI loop mount.
* `EINTR` handling is unit-tested on the retry helper; the signal interruption of the real syscalls is not provoked.
* The container entrypoint script and the compose file were syntax/config checked only, not run in a container.
* ACL-based exposure of the snapshot directory.
