## Review Focus

1. **Scanner changes (Tasks 5–7) must not purge or re-home a library.** Symlink following and album-artist election change which rows a scan produces. The tests that matter: a link loop and a link above the root end the walk; one real file behind two links is one song and a *new* link never takes a song from the path it is filed under; an upgraded library does not silently split or merge albums (Task 7 `existing_album_not_resplit`), and a drive that vanishes purges nothing (Task 5 `mass_missing_stands_down`).
2. **History is carried, never lost, on a purge.** A replaced copy (mp3 -> flac) hands plays, stars, ratings, playlist places and bookmarks to the new copy before the old row goes (Task 5 `replaced_file_hands_history_to_copy`), and a place the user already has on the copy is kept.
3. **Identification order (Tasks 12–13) with no AcoustID key.** kima-rs ships with an empty AcoustID key (D-124); with it every new AcoustID step must be skipped without a request, cost, error, or a changed answer for any track (Task 12 `no_key_ladder_unchanged`).
4. **Subsonic promises equal behaviour (Task 15):** what `getTranscodeDecision` promises is what `stream`, `getTranscodeStream`, `hls` deliver, and a forged `transcodeParams` is an error, never a stream.
5. **Removed routes answer 404, not 405/401,** and no kima-rs frontend (`frontend/`, `kima-web`) still calls one (Task 3 `removed_routes_are_404`). **Owner (2026-11-11):** `GET /api/plays` answers 405 because `POST /api/plays` shares the path; accepted as D-172. The Appendix C loop found one more served route, `DELETE /api/playlists/:id/items` (D-173, to decide).
