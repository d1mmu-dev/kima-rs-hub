# Divergences from upstream Kima

Every place where kima-rs behaves, stores or exposes something differently from
upstream kima-hub (reference: v1.11.0) is recorded here, so it can be revisited
later: fixed to match, kept on purpose, or rethought.

**Rule:** any change that makes kima-rs differ from upstream adds an entry in the
same commit. Entries are never deleted, only given a new status.

Status: `open` (not yet reviewed) · `accepted` (keep, intended) ·
`to-fix` (should match upstream later) · `to-decide` (needs thought) · `resolved`

| ID | Area | Upstream | kima-rs | Why | Status |

| D-002 | Data | — | No import from an existing Kima install in v1 | Scope; possible later importer | to-decide |

| D-005 | Auth | bcrypt password hashes | argon2id | Modern default; bcrypt verify only needed if importing (see D-002) | accepted |
| D-006 | Runtime | supervisord running postgres, redis, node, next, 2 Python services | Postgres + one `kima` binary | Footprint | accepted |
| D-007 | Frontend | Next.js server (`next start`) | Static export served by axum | No Node runtime; features that need a server get patched to client-side | accepted |

| D-012 | Frontend | `/share/[token]` and `/library` are server-rendered (share page can emit link-preview metadata) | Client-rendered only; share links show no rich preview | Static export has no server rendering | to-decide |
| D-013 | Auth | Also accepts an express-session cookie (`req.session.userId`) | Bearer JWT, API key, or `?token=` only | No cookie sessions in kima-rs; the frontend uses bearer tokens anyway | accepted |
| D-014 | Events | SSE tickets stored in Redis (`sse:ticket:*`, 30 s) | Held in an in-memory map with a 30 s TTL | No Redis; single process | accepted |
| D-015 | Auth | User cache with 30 s TTL in the auth middleware | Version check hits the DB on every request (indexed PK lookup) | Simpler; add a cache only if profiling shows a need | open |
| D-016 | IDs | cuid string IDs | UUIDv7 | Native Postgres `uuid` type, time-ordered | accepted |
| D-017 | Config | No `KIMA_DATA_DIR`, `KIMA_FRONTEND_DIR`, `KIMA_BIND_HOST` (paths fixed by the image; Next.js serves the frontend) | New env vars `KIMA_DATA_DIR` (default `/data`), `KIMA_FRONTEND_DIR`, `KIMA_BIND_HOST` (default `0.0.0.0`) | One binary serves everything and must be runnable outside Docker | accepted |
| D-018 | Secrets | Entry script generates `SESSION_SECRET` / `SETTINGS_ENCRYPTION_KEY` (persisted in the all-in-one image; regenerated every start in split images when unset) | The binary generates both once into `<KIMA_DATA_DIR>/secrets.json` (mode 0600); env vars override; a corrupt file stops startup instead of being replaced | Same behaviour on every deployment; never silently loses the encryption key | accepted |
| D-019 | Users | Usernames unique and matched case-sensitively | Unique and matched case-insensitively (`lower(username)`); login with "ANA" finds "Ana" | Prevents look-alike duplicate accounts | open |
| D-020 | Users | First-user check (`count == 0`) not serialised; two concurrent first sign-ups could both become admin | Registration runs under a Postgres advisory lock | Race fix | accepted |
| D-021 | Health | `/health` reports db, redis, embedding write path, Lidarr and analyzer liveness | Reports `{"status","checks":{"db"}}` only; more checks are added as subsystems land | Only the DB exists in M0 | open |
| D-022 | API errors | Validation failures return `details` as a zod issue array | `details` is a single human-readable string | No zod; simpler | open |
| D-023 | Auth | Login does not trim the username; register does not trim either | Both trim surrounding whitespace | Avoids "ana " accounts that can never log in from a phone keyboard | open |
| D-024 | Auth | 2FA login step, change-password, admin user management, stream tickets, API keys exist | Change-password, admin user management (list, create, delete) and stream tickets are present (M1); 2FA + API keys arrive in M8 | Milestone order | open |
| D-025 | Onboarding | `/onboarding/lidarr`, `/audiobookshelf`, `/soulseek`, `/enrichment` steps; `complete` re-initialises Lidarr/Audiobookshelf and syncs audiobooks | `status`, `register`, `complete`; `lidarr`, `audiobookshelf`, `soulseek` exist as stubs (admin only, as upstream): a disabled payload returns upstream's `{"success": true, "tested": false}` and saves nothing, an enabled one returns 400 `{"error": "<Integration> integration is not available yet"}`; no `enrichment` step, and `complete` only marks onboarding done | Those integrations arrive in M6/M7 | open |
| D-026 | Frontend | `/manifest.webmanifest` generated by a Next.js route handler | Static file in `public/`; served without the `Cache-Control: public, max-age=3600` header the route handler sent | Static export | accepted |
| D-027 | Frontend | `next/image` optimisation via the Next server | `images.unoptimized: true`; images served as-is | Static export | open |
| D-028 | Image | Bundles Redis, Node, Next.js server, Python analyzers; supervisord | Bundles Postgres + kima only; tini + a bash entrypoint; Postgres skipped when `DATABASE_URL` is set | Footprint (see D-006); external Postgres supported | accepted |
| D-029 | Image | Postgres listens inside the container with a password | Bundled Postgres trusts local connections on 127.0.0.1 only | Never exposed outside the container; no password to manage | to-decide |
| D-030 | Frontend | Nav and sections show only the features that are available (as configured upstream) | M0 ships the upstream nav ungated, so unported sections are reachable and their API calls 404 | Gating lands in M1 with the first real feature flag (`/system/features`) | open |
| D-031 | API | CORS reflects the request origin with `credentials: true` | `Access-Control-Allow-Origin: *` when `ALLOWED_ORIGINS` is unset, otherwise only the listed origins; no `Access-Control-Allow-Credentials` | Bearer tokens, not cookies; same-origin use (the bundled frontend) is unaffected | open |
| D-032 | Config | No library watch, organize or transcode-cache settings | New optional env vars `KIMA_WATCH_MODE` (`auto`, `poll` or `off`; default `auto`), `KIMA_WATCH_POLL_SECS` (default `60`), `KIMA_ORGANIZE_TARGET` (unset: copy mode unavailable), `KIMA_TRANSCODE_CACHE_MB` (default `2048`) | kima-rs watches the library, offers an on-disk organizer and caches transcodes; upstream rescans on a schedule and has no organizer | accepted |
| D-033 | API | An open SSE stream ends when its user's sessions are revoked (token version bumped) | Open SSE streams outlive a session revocation | A revoked user must not keep receiving events; `kima_api::revoke_sessions` publishes the revoke event | accepted |
| D-034 | API | SSE sends `{"type":"resync"}` after a broadcast lag | Redis pub/sub has no equivalent; missed events are lost silently | A slow client learns it missed events and can refetch | open |
| D-035 | API | `POST /api/auth/stream-ticket` also returns `token` (same value as `ticket`) | `{ticket, expiresIn}` only | `token` is a kima-rs addition kept alongside upstream's `ticket` and `expiresIn`; no frontend consumer of this endpoint exists in the repo yet | open |
| D-036 | API | `POST /api/auth/change-password` is last-write-wins under concurrent changes | The update is conditional on the token version the handler read; a concurrent change returns 409 `{"error":"Password was changed concurrently, please retry"}` | Two simultaneous changes cannot both pass the current-password check and silently overwrite each other | open |
| D-037 | API | `DELETE /api/auth/users/:id` may delete the last admin | Refused with 400 `{"error":"Cannot delete the last admin"}`, serialised under an advisory lock; an unparsable id is 404 | A server with no admin cannot be recovered from the UI | open |
| D-038 | API | `GET`/`POST /api/system-settings` carry the full integration settings, behind requireAdmin | Admin only; the M1 subset is `{registrationOpen, libraryRoot}` (POST accepts `registrationOpen`) | Other settings arrive with their features; `libraryRoot` is added for the library scanner | open |
| D-039 | Library | Albums are identified by (album artist, normalised title, year when known); the same title with different years stays two albums, and no year merges with no year only | Upstream identifies albums by artist and title (via MBID or normalised title) and keeps one row | Remasters stay separate while multi-folder albums (CD1/CD2) still merge; decided in spec §9 | open |
| D-040 | Library | Tracks that vanish from disk are flagged `missing_since` and removed after 7 days; a new path with a matching content fingerprint re-points the old track | Upstream removes tracks whose files are gone on the next scan | Plays and playlist entries survive an unmounted drive or an external move | open |
| D-041 | Library | Search vectors use the `simple` text-search config (name or title weight A, artist B, album C), maintained by triggers | Upstream searches with Postgres full text over its own columns | No stemming or accent folding in M1; Task 11 decides search behaviour.; renames refresh dependent album and track vectors via triggers | open |
| D-042 | Library | Folder fallback splits artist from album only on a spaced separator (` - `, ` – `, ` — `); the scene rule needs no spaces and at least two hyphens; the grandparent folder wins over a split of the album folder; `Artist/01.mp3` takes the folder as the artist; `CD1`/`Disc 2` subfolders are skipped (their number is the disc fallback); a numeric-only part is never an artist; the album drops a leading `Artist - ` only when it equals the resolved artist, and drops a year prefix or suffix | Upstream splits on any `-` (so `Sleater-Kinney`, `Jay-Z`, `AC-DC` become `Sleater`, `Jay`, `AC`), can return `1997` as the artist, prefers the album-folder split over the grandparent, and uses the whole folder name as the album | Mis-resolves common band names in a messy library; year-prefixed and multi-disc layouts are supported (spec 4.1) | open |
| D-043 | Library | `GET /api/library/cover-art/:id` takes an album id; the cover comes from embedded art (front cover preferred) or a `cover`/`folder`/`front` image next to the album's first tracks, resized to fit `size` (never upscaled), cached as JPEG q85 under `<data_dir>/artwork/<album>/<size or orig>.jpg`, with `Cache-Control: private, max-age=86400`; `?url=`, `native:` and `audiobook__` ids are not served (404); a non-numeric `size` is 400; size snaps up to 64, 128, 256, 512 or 1024 (above 1024 gives 1024) | Upstream serves cover hashes, native cache files, external URLs (proxied), Deezer fallbacks and audiobook covers with `immutable` one-year caching | M1 has no external artwork sources; the cache is not invalidated when the source image changes (delete `artwork/<album>` to refresh) | open |
| D-044 | Library | A scan sends `scan:progress` `{jobId, progress}` (percent, every 1 %) and `scan:complete` `{jobId, result}` to the user who started it | One event shape, `{"type":"library:progress","job":"scan","done":n,"total":m}`, to every user (`user_id: None`), at most 4 per second, with a final event when the reconcile ends; no `scan:complete`; a reconcile runs on every start (skipped when one is already queued or running), and on a watcher overflow or error, never on a schedule; ordinary watcher events enqueue single-file `path` jobs, not reconciles | Shared with organizer progress; scans are no longer per-user requests. The scan-status UI that reads `scan:progress` is not ported yet | open |
| D-045 | Library | An album's year is the year of whichever file created the album row | The album year is the most common track year within one (folder, album artist, album title) group, ties to the earliest; tracks whose own year differs are flagged `yearConflict`, and their own year is kept on the track | One album folder with mixed track years stays one album (spec §4.3) | open |
| D-046 | Library | The scan walks every file and folder, hidden ones included, and flags every vanished track missing, even when the library root comes up empty | Dot-prefixed files and folders (hidden, `._` AppleDouble) are skipped. A reconcile that finds no audio files while the library has present tracks (an unmounted disk leaving an empty mount point) marks nothing missing and purges nothing (`root_empty_guard`), and a single-file update for a vanished file returns `RootUnavailable` when the root is missing, unreadable or empty | A disk that is not mounted must never start the 7-day purge clock for the whole library (Review Focus 2); AppleDouble files are not audio | open |
