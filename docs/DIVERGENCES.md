# Divergences from upstream Kima

Every place where kima-rs behaves, stores or exposes something differently from
upstream kima-hub (reference: v1.11.0) is recorded here, so it can be revisited
later: fixed to match, kept on purpose, or rethought.

**Rule:** any change that makes kima-rs differ from upstream adds an entry in the
same commit. Entries are never deleted, only given a new status.

Status: `open` (not yet reviewed) · `accepted` (keep, intended) ·
`to-fix` (should match upstream later) · `to-decide` (needs thought) · `resolved`

| D-040 | Library | Tracks whose files vanish are flagged `missingSince` (cleared when the file is back at the same path) and are never deleted | Vanished tracks are flagged `missing_since` and purged after 7 days missing; a new path whose content fingerprint matches a missing track re-points that track (same id), keeping its plays and playlist entries | The 7-day purge keeps truly deleted files from piling up while still surviving an unmounted drive; the fingerprint re-point keeps history across external moves and renames | open |
| D-041 | Library | Search vectors use the `simple` text-search config (name or title weight A, artist B, album C), maintained by triggers | Upstream searches with Postgres full text over its own columns | No stemming or accent folding in M1; Task 11 decides search behaviour.; renames refresh dependent album and track vectors via triggers | open |
| D-042 | Library | Folder fallback splits artist from album only on a spaced separator (` - `, ` – `, ` — `); the scene rule needs no spaces and at least two hyphens; the grandparent folder wins over a split of the album folder; `Artist/01.mp3` takes the folder as the artist; `CD1`/`Disc 2` subfolders are skipped (their number is the disc fallback); a numeric-only part is never an artist; the album drops a leading `Artist - ` only when it equals the resolved artist, and drops a year prefix or suffix | Upstream splits on any `-` (so `Sleater-Kinney`, `Jay-Z`, `AC-DC` become `Sleater`, `Jay`, `AC`), can return `1997` as the artist, prefers the album-folder split over the grandparent, and uses the whole folder name as the album | Mis-resolves common band names in a messy library; year-prefixed and multi-disc layouts are supported (spec 4.1) | open |

| D-047 | Library | Library changes are picked up by a scheduled rescan | The library root is watched (`notify`, debounced 2 s, then held until the file's size and mtime stop changing, so a file still being copied is read once complete); each settled file queues a `path` job, folder renames and deletes expand to their files (deletes via the DB), hidden paths and paths in the organizer's ignore set are skipped; a watcher error or event overflow queues a reconcile. `auto` falls back to polling when native watching fails (for example the inotify watch limit, reported as `fs.inotify.max_user_watches` in `lastError`); `poll` uses `KIMA_WATCH_POLL_SECS`; `off` watches nothing. `GET /api/library/watch-status` (admin) returns `{mode, active, lastError}` | Upstream rescans on a schedule; there is no watcher or status endpoint.
