# M2 Subsonic Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phone and desktop music apps (DSub, Symfonium, Feishin, Amperfy, Substreamer) can browse, search, stream, download, scrobble, star, rate, edit playlists, sync the play queue and save bookmarks against a kima-rs server. They authenticate with per-app tokens that can be revoked, including through the classic token+salt handshake.

**Architecture:** A new crate `kima-subsonic` serves the OpenSubsonic API under `/rest/*`. It builds a format-neutral `Node` tree that two writers turn into XML or JSON. It is a thin adapter over `kima-db` read models and a new shared `kima_api::media` module, split out of the M1 stream and cover handlers, so `/api` and `/rest` serve media through one code path. App tokens live in `api_keys` as a SHA-256 lookup hash plus an XChaCha20-Poly1305 ciphertext under the new `kima_core::cipher`. A failed-login limiter in `kima_api` guards password auth on both APIs. Two carried-forward items also land: a cron scheduler in `kima-jobs` (a daily safety-net reconcile) and an `AdminUser` extractor.

**Tech Stack:** Rust 2024, axum 0.8, sqlx 0.8, tokio, Postgres 17. New crates: `chacha20poly1305` 0.10, `hkdf` 0.13 and `hmac` 0.13 (both fit the workspace's `sha2` 0.11), `md-5` 0.11, `hex` 0.4, `quick-xml` 0.37, `croner` 2 (+ `chrono` 0.4), `httpdate` 1. Dev only: `insta` 1, `reqwest` 0.12 (`default-features = false`). The forked Next.js 16 frontend (static export) and Playwright.

- **App tokens:** 32 OS-RNG bytes as 64 lowercase hex characters. Names are 1–100 characters after trimming. A user holds at most 50. The ciphertext is `0x01 ‖ nonce (24) ‖ ciphertext ‖ tag (16)`, with AAD = `b"api_keys:"` followed by the 16 raw bytes of the row's UUID. The key is HKDF-SHA256 over `SETTINGS_ENCRYPTION_KEY`, with info `b"kima-rs cipher v1"` and no salt.
- **Limiter:** keyed by (TCP peer IP, lower-cased username). Failures 1–5 are free. After the f-th consecutive failure (f ≥ 5), the key is blocked for `min(2^(f−4), 900)` seconds: 2 s, 4 s, 8 s and so on, capped at 15 minutes. A success clears the key. A key with no failure for 15 minutes is forgotten. The store holds at most 100 000 keys and evicts the oldest last failure first. (Spec §5.7 writes the exponent as `failures − 5`. Its own tests, "the 6th attempt within the backoff is refused" and §10.3 step 11, need the block to start at the 5th failure, and its listed sequence "2 s, 4 s, 8 s" starts at 2 s. This formula meets all three.)
- **Paging caps:** `size`/`count`/`*Count` are at most 500. Defaults are given per endpoint in spec §4.
- **Never log credentials.** `/rest` request spans record `method` and `path` only. No `tracing` field in `kima-subsonic` may carry `p`, `t`, `s`, `apiKey` or a token.
- **New env vars, all optional:**
  - `KIMA_LIBRARY_SYNC_CRON`: default `0 4 * * *` (UTC). `off` disables it. An invalid expression fails startup.
  - `KIMA_ARTWORK_CACHE_MB`: default `512`.
  - `KIMA_PUBLIC_URL`: unset means empty. It must start with `http://` or `https://`, and a trailing `/` is stripped.
- **Ids:** M1 UUID strings. The accepted prefixes are `ar-`, `al-`, `tr-`, `artist:` and `album:`, only where spec §4 names them. A non-UUID id is 70. The only music folder is `1`, and `musicFolderId` is ignored.

## Review Focus

1. **A whole-library sync by paging an empty `search3`.** Symfonium asks for `songCount=500&songOffset=0`, then 500, 1000 and so on, until a short page comes back. Every present track must come back exactly once across the pages, with no gaps or repeats, even when titles tie. The order is `sort_name`/title, then `id`. The test lives in Task 11.
2. **Tag text that breaks XML.** Titles with `&`, `<`, `>`, `"` and `'`, and tags with C0 control characters (`\u{1}`, `\u{1b}`, which real-world ID3 tags contain), must give well-formed XML that a strict parser accepts. Characters that XML 1.0 forbids are dropped, and JSON carries the text unchanged. The test lives in Task 5.
3. **Usernames typed with different case.** A user stored as `alice` signs in as `Alice` from a phone keyboard, using `t`/`s`, `p=` and `apiKey`+`u`. All three must work, and the limiter must count `Alice` and `alice` as one key. The test lives in Task 6.
4. **Download of a non-ASCII file name.** `Björk – Jóga "live"; take 2.flac` must give `Content-Disposition: attachment; filename*=UTF-8''<RFC 5987 percent-encoded>`, with no raw quote, semicolon or non-ASCII byte in the header. The test lives in Task 12.
5. **Parameters split between the query string and a POST body, with repeated keys.** Feishin posts `savePlayQueue` with credentials in the query and `id=a&id=b&id=c` in a form body. The merged multimap must keep all three ids in order, and query values come before body values. The test lives in Task 5 (params) and Task 13 (the endpoint).
