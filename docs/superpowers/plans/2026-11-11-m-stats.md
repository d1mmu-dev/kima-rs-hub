# M-STATS S1 (stats backend, plays-only parts) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** kima-rs serves the ten upstream `routes/stats.ts` endpoints under `/api/stats` with upstream's request validation, error texts and response shapes. Everything that is made of `plays` (plus the library rows they join) is computed exactly as upstream computes it; everything that needs audio analysis (energy, valence, bpm, key, instrumentalness), audiobook/podcast progress or the job/cache subsystems answers the value upstream itself answers for a library with none of that data, so the unchanged v1.12.3 stats page renders without a 404 and without inventing a figure. The play-history audit (false starts) and its `play_audit_ignore` table are ported in full. At the end `GET /api/system/features` sends `"stats": true` (D-170) and the roadmap row points here. **S2** (analysis-dependent figures after M4's analysis outputs, `spoken` after M6, `system` after M7) and the stats **page** in `kima-web` (M10) are not done here.

**Architecture:** No new crate, no new dependency. `kima-db` gets one migration (`play_audit_ignore`), a `stats` module (the shared listen walk, the figures, the audit) and one extra hand-off statement in `library::hand_over`. `kima-api` gets `routes/stats.rs` (+ `routes/stats/args.rs` for upstream's query-string coercions) merged in `routes/mod.rs`. `kima-api-types` gets `stats.rs` (hand-written wire DTOs, as for the other routes) plus fixtures. The listen walk is upstream's recursive SQL translated to kima-rs column names and run as runtime `sqlx::query_as` (the period clause is a closed enum, so the text is not static); every such query is exercised by an integration test on an isolated database. The audit's grouping is a pure Rust port of `listensOf` and is unit-tested with upstream's own cases.

**Tech Stack:** unchanged (Rust 2024, axum 0.8, sqlx 0.8, tokio, time, Postgres 17). Test-only: `axum_test`, `#[sqlx::test]`.

## Review Focus

1. **One definition of a listen.** The recursive walk (Task 2) is what every listening figure, the player's play count and the tracks slices count. Its boundary rule (a row exactly one listen-window after the listen's start opens a new listen, `>=`) must agree with `plays::record`'s duplicate window (strict `<`/`>` bounds) and with the audit's pure grouping (Task 9, `<`). Test `walk_agrees_with_audit_grouping` compares them on generated histories.
2. **Time zones on `timestamptz`.** Upstream's `playedAt` is `timestamp(3)` *without* zone, holding UTC, so upstream writes `p."playedAt" AT TIME ZONE 'UTC' AT TIME ZONE $tz`. kima-rs `plays.played_at` is `timestamptz`; the correct translation is the **single** `p.played_at AT TIME ZONE $tz` (yields the local wall-clock `timestamp`). Copying the double form onto a `timestamptz` shifts every bucket by the zone offset twice. Tests pin a Sunday 23:30 UTC play to Monday 00 in `Europe/Warsaw`.
3. **Deletes take track ids only and re-derive verdicts.** `remove` must recompute verdicts from current rows inside the request, skip ignored tracks, and delete only `user_id = <caller>` rows; a stale or forged list can never delete a heard listen or another user's row.
4. **No invented figures.** Analysis-dependent fields are exactly what upstream returns when no track has analysis values (`shape: []`, `signature.key: null`, `ownedVsPlayed: []`, `hourly: []`, `drift[].energy/valence/bpm: null` with real `plays`), not zeros or guesses.

**Upstream [V]:** `stats.ts:145-215`. pub async fn collapse(pool: &PgPool, user: Uuid) -> sqlx::Result<u64>;
